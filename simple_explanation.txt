# Simple Explanation of the Plant Disease Classification System

## 1. The Problem We Are Solving

Plant diseases damage crops, reduce farmer income, and lower food quality. But there is a big problem:

- Most farmers and gardeners cannot tell **which disease** a plant has just by looking at it.
- Real experts (plant doctors / agronomists) are few, expensive, and often far away.
- By the time a farmer finds out what is wrong, the disease has already spread.
- Wrong guesses lead to wrong chemical sprays, which waste money and harm the environment.

So the core problem is: **"How can a farmer quickly and cheaply find out what disease a plant has, using only a photograph?"**

Our system tries to solve this by using Artificial Intelligence (AI) to look at a plant photo and tell the farmer the most likely disease, along with how confident the AI is.

**Important note:** This system is an *assistant*, not a replacement for an expert. It gives an AI-assisted guess, and the farmer should confirm important decisions with a real agricultural expert.

---

## 2. How It Works Step by Step

Think of it as a pipeline — one step passes its output to the next step.

1. **User Uploads an Image**
   - The farmer takes a photo of the plant leaf with a phone or camera.
   - The photo is uploaded through the web application.

2. **Image Processing (OpenCV + Pillow)**
   - The system first checks the image is safe and valid (correct file type, not too large, not corrupted).
   - The image is resized to a fixed size (224 x 224 pixels) because the model was trained on this exact size.
   - The image is converted to RGB colour format.
   - Any required normalization (scaling of pixel values) is applied so that the image looks the same to the model as the training images did.

3. **Model Analysis (EfficientNetB3)**
   - The processed image is passed to the trained **EfficientNetB3** deep learning model.
   - The model compares the image's visual features (spots, colour, texture, leaf shape) with what it learned during training.
   - It outputs a probability for each of the **38 possible classes** (plant + disease combinations, including healthy plants).
   - The system picks the top 3 highest probabilities.

4. **Result Display**
   - The app shows the predicted **plant name** and **disease name**.
   - It shows the **confidence percentage**.
   - It shows a **confidence state**:
     - "High" = the AI is very sure
     - "Review recommended" = the AI is somewhat sure
     - "Uncertain" = the AI is not sure; treat the result with caution
   - It shows the **top 3 alternatives** so the user sees what else it could be.
   - It shows **educational info** about the disease (symptoms, prevention) from a reviewed knowledge base.

## 3. The Machine Learning Model

**Model name:** EfficientNetB3 (with ImageNet pre-trained weights)

**What I built and trained:**
- I used the **PlantVillage-style dataset**, where leaf images are already grouped into plant + disease folders.
- I loaded all images at **224 x 224 pixels** in RGB, so that every image the model sees has the same size and format.
- I used **EfficientNetB3** as the backbone (the "feature extractor") without its original top classification layer.
- On top of the backbone, I designed my own classification head: a global max pooling layer, a 256-unit dense (ReLU) layer, a dropout of 0.3 (to prevent overfitting), and a final **38-unit softmax** layer that gives one probability for each of the 38 classes.
- I trained the model in two stages using **transfer learning**: in stage one I froze the pre-trained base and trained only my new head; in stage two I unfroze the base and fine-tuned it at a lower learning rate.
- I applied **data augmentation** during training (flipping, rotating, zooming) so the model does not memorise images but learns general patterns.
- I trained with batch size 32 for around 40 epochs and saved the best-performing version of the model.
- The trained model reached **99.54% accuracy on the validation data**.

**Why EfficientNetB3 and not a simple CNN?**
- A basic CNN trained from scratch needs huge amounts of data and gives lower accuracy.
- EfficientNetB3 is already trained on millions of images (ImageNet), so it already "knows" how to detect edges, shapes, textures, and colours.
- We only teach it the *new* task (plant diseases) using our dataset — this is called **transfer learning**. It gives high accuracy with far less training time and data.

**Why 38 classes?**
The dataset groups images by plant and condition. For example: "Tomato___Late_blight", "Tomato___healthy", "Potato___Early_blight", and so on. There are 38 such combinations in this dataset. The model outputs one probability per class, and we map the highest index back to its human-readable name using a saved `labels.json` file.

**Why I trained my own model:**
Rather than depending on someone else's saved model file, I trained my own model from scratch using the dataset. This gives me full control over the class ordering, the preprocessing settings, and the evaluation — and lets me document every artifact (the model file, the label list, the preprocessing settings, and the evaluation report) so the system is reproducible and explainable.

**Honest limitation:** The 99.54% figure is on the PlantVillage-style dataset, where photos are clean and laboratory-like. Real field photos (poor light, blur, background clutter) will give lower accuracy. So the system clearly shows confidence levels and warns that results are AI estimates, not guaranteed diagnoses.

## 4. The Technology Stack

This is the set of tools and languages used to build the whole system (from the photo-upload screen to the AI model):

### Frontend (what the user sees in the browser)
- **Next.js (App Router)** – the web framework that builds the pages.
- **TypeScript** – a safer version of JavaScript that catches errors early.
- **Tailwind CSS** – for styling and making the pages look clean and responsive (works on phone and desktop).

### Backend (the server that runs the AI and handles requests)
- **Python 3.11+** – the main programming language of the backend.
- **FastAPI** – a fast Python web framework that receives the image, runs the model, and returns the result.
- **Pydantic** – validates that data (image requests, results) has the correct shape and types.

### Machine Learning (the AI part)
- **TensorFlow / Keras** – the library used to build, train, and load the EfficientNetB3 model.
- **EfficientNetB3** – the deep learning model architecture (pre-trained on ImageNet).
- **NumPy** – for numerical/matrix operations on image arrays.
- **Pillow (PIL)** – for opening, decoding, and resizing uploaded images.
- **OpenCV** – for image reading and image-processing operations (resizing, colour conversion, validation).
- **Matplotlib / Seaborn** – for plotting training graphs and confusion matrices.

### Database and Storage
- **Supabase PostgreSQL** – the database that stores users, predictions, feedback, and disease information.
- **Supabase Auth** – handles sign-up, sign-in, and secure login sessions.
- **Supabase Storage** – stores uploaded plant images in a **private** bucket (only the owner can see them).

### Security
- **Row Level Security (RLS)** – database rules so one user can never read another user's predictions or images.
- **Bearer-token authentication** – each request proves who the user is.
- **Private storage + signed URLs** – images are not publicly accessible.

### Development and Deployment
- **Docker / Docker Compose** – to run the frontend and backend together locally.
- **pytest** – for automated testing of the backend and model.
- **Vercel** – deployment platform for the Next.js frontend.
- **Render / Railway / Fly.io** – deployment platform for the FastAPI backend (any Python-capable host).
- **Git / GitHub** – for version control and code sharing.

### One-line summary of the stack
> **Next.js + TypeScript + Tailwind** (frontend) → **FastAPI + Python** (backend) → **TensorFlow/Keras EfficientNetB3** (AI model) → **Supabase** (database, login, image storage).
